# Лендинг магазина спортивного питания

Демо-шаблон для портфолио и холодной рассылки. Реализация ТЗ из [description.md](description.md).

Концепция — **«панель состава»**: язык этикетки (таблица нутриентов, моноширинные цифры,
хайрлайны) становится языком всего сайта. Данные вместо крика — это одновременно и приём
дизайна, и юридическая страховка: реклама БАД не может обещать лечение, но может показывать состав.

Архитектура: **ядро / конфиг клиента / кастомизация**. Подмена под нового клиента — один файл
и одна папка с фото.

## Запуск

```bash
npm install
npm run dev
```

Сборка и локальный просмотр продакшн-версии:

```bash
npm run build && npm run preview
```

## Перенос на клиента за 20 минут

1. Правите `src/config/client.config.ts` — там всё, включая падежи города.
2. Складываете съёмку в `public/client/` и меняете пути в конфиге и в компонентах блоков 08, 10, 11.
3. Правите `src/data/products.ts` под реальный ассортимент. **Важно:** `id` товаров, на которые
   ссылается `matrix.ts`, должны остаться прежними, иначе конструктор перестанет собирать наборы.
4. Проверяете, что хардкода не осталось:

   ```bash
   grep -rn "Нижнекамск\|900 000-00-00\|Химиков" src/ --include="*.astro" --include="*.ts" | grep -v client.config
   ```

5. Прогоняете приёмку: `npm run build && npm run preview`, затем `npm run qa`.

Тёмная тема и фирменный цвет включаются в конфиге (`theme`, `accent`) — переопределять
CSS не нужно.

## Генерация ассетов

```bash
npm run assets   # секвенция банки, карточки товаров, плитки категорий, OG
npm run fonts    # подрезка шрифтов под используемые символы
```

**Секвенция банки** (`tools/gen-seq.mjs`) — 36 кадров поворота на 360°, без 3D-софта:
этикетка рисуется один раз плоской текстурой, затем нарезается на 72 вертикальные полосы
и раскладывается по цилиндрической проекции `x = R·sin φ` с шириной полосы `∝ cos φ`.
Сверху градиент затенения и блик. Все 36 кадров весят 456 КБ.

**Шрифты** подрезаются под реальный набор символов и под используемый диапазон веса
(дисплей 700–800, текст 400–600, данные 400–500): 177 КБ → 84 КБ.

## Осознанные отступления от ТЗ

Каждое — в пользу целей, которые ставит само ТЗ.

**1. GSAP + ScrollTrigger не используются.**
ТЗ называет эту связку, но при ней страница ломалась: ScrollTrigger в паре с Lenis
пропускает срабатывания при программном скролле (переход по якорю, восстановление позиции
при перезагрузке, поиск по странице) — секции оставались невидимыми. Появления переведены
на `IntersectionObserver` + CSS-переходы. Визуально то же самое, поведение надёжнее,
минус 46 КБ gzip — это и дало Performance 98 на мобильном. Lenis оставлен ради инерционного
скролла, как и просило ТЗ.

**2. `--steel` изменён с `#8A9299` на `#5D656C`.**
Исходный тон даёт контраст 2.4:1 на карточках при требовании ≥ 4.5:1 из раздела 8 того же ТЗ.
Оттенок сохранён, светлота опущена до нормы: 5.1:1 на бумаге, 4.6:1 на карточке.

**3. `--heat` изменён с `#FF5A1F` на `#E04200`, добавлен `--heat-ink` `#B33200`.**
Та же причина: исходный оранжевый не проходил даже смягчённую норму 3:1 для крупного кегля.
Крупные цифры результата берут `--heat`, мелкие подписи вроде бейджа «осталось 3» — `--heat-ink`.
В тёмной теме ограничение снимается и возвращается исходный `#FF5A1F`.

**4. Потолок H1 в первом экране опущен до 70px** (шкала ТЗ — до 104px).
Шкала рассчитана на заголовок в 3–4 слова; варианты 1 и 4 длинные, и при 104px заголовок
занимал весь первый экран, а кнопки уходили за сгиб. Сама шкала не тронута — размер вынесен
в переменную `--h1-size`, секция опускает потолок у себя.

**5. Разворот этикетки идёт сразу после первого экрана, а не «становится блоком 09».**
В ТЗ есть противоречие: раздел 3.5 говорит, что этикетка разворачивается в блок «Цифры
магазина», а раздел 4 ставит этот блок девятым. Панель, в которую разворачивается этикетка,
сделана продолжением первого экрана (позиции в наличии, самовывоз, проверка кода, лет на рынке),
а блок 09 остался на своём месте. Жест «товар → данные → доверие» сохранён, порядок блоков — тоже.

## Что нужно доделать перед боевым запуском

- [ ] **Фотографии.** В демо на местах съёмки стоят слоты с номером кадра из брифа (раздел 6.1 ТЗ).
      Их девять: витрина, полки, продавец, код на банке, проверка кода, собранный заказ,
      пробники, портрет для отзыва, постер видео-отзыва.
- [ ] **Политика ПДн.** В `src/pages/privacy.astro` типовая редакция. Состав данных, сроки
      хранения и перечень получателей у каждого бизнеса свои — текст обязан проверить юрист клиента.
- [ ] **Метрика.** `metrika: 0` в конфиге отключает счётчик. Поставьте номер — цели
      `quiz_start`, `quiz_complete`, `calc_complete`, `wa_click`, `form_submit`, `phone_click`
      уже расставлены в разметке.
- [ ] **Приём финальной формы.** Пустой `forms.formspreeId` — заявка уходит в WhatsApp.
      Укажите id, чтобы форма отправлялась на почту, с откатом в WhatsApp при ошибке.
- [ ] **Проверка на iOS Safari.** Секвенция на `canvas` — самое хрупкое место в этой связке,
      прогоните первый экран на живом устройстве.
